# API Specification

DER Builder is an ESM-only package with controlled entry points. Paths not
listed here are private and may change without notice.

## Core entry points

The package root and `@pkistudio/derbuilder/core` expose the same Core API:

- `parseAsn1Definition(source): Asn1SchemaModule`
- `validateSchemaModule(schema): SchemaDiagnostic[]`
- `validateInstance(schema, typeName, input): InstanceDiagnostic[]`
- `createInstance(schema, typeName, input): InstanceDocument`
- `encodeValue(schema, type, input): Uint8Array`
- `resolveDefinedType(schema, typeName): Asn1Type`
- `bytesToHex(bytes): string` and `hexToBytes(text): Uint8Array`
- `resolveObjectIdentifierName(value, schemaNames?)`
- `builtInOidNames`, `pkiComponentDefinition`, `exampleDefinition`,
  `exampleSchema`, and `exampleInput`
- `DER_BUILDER_VERSION` and `DerBuilderError`

`InstanceDocument` contains `moduleName`, `typeName`, and `der: Uint8Array`.
Generation APIs throw `DerBuilderError` for invalid direct input; callers that
need multi-error reporting should call diagnostics first.

## Validation entry point

`@pkistudio/derbuilder/validation` exposes:

- `validateSchemaModule()` and schema diagnostic types;
- `validateInstance()` and instance diagnostic types; and
- `parseDefinitionBundleJsonWithDiagnostics()`,
  `validateDefinitionBundle()`, and bundle diagnostic types.

Every diagnostic contains `severity`, `code`, `message`, and a string-array
`path`. Validation functions return diagnostics and do not throw for ordinary
invalid input.

## App entry point

`@pkistudio/derbuilder/app` exposes `initDerBuilder()`, Definition Bundle
helpers and types, UI Profile types, and `namedObjectDefinitionBundles`.

```ts
const app = initDerBuilder({
  mount: '#app',
  schema,
  input
});
```

`mount` accepts a selector or an `HTMLElement`. Initial state may instead use
`bundle` and optional `bundleEntry`; a bundle takes precedence over `schema`.
An explicit `input` then overrides the loaded sample/default input.

The returned `DerBuilderApp` provides:

```ts
build(options?: { typeName?: string; input?: unknown; openViewerTab?: boolean }):
  Promise<DerBuilderBuildResult>;
loadBundle(bundle: DefinitionBundle, entryIdOrTypeName?: string): void;
loadSchema(schema: Asn1SchemaModule): void;
loadInput(input: unknown): void;
close(): void;
```

A successful build result has `ok: true`, `document`, `schemaDiagnostics`, and
`instanceDiagnostics`. A failure has `ok: false`, `error`, and both diagnostic
arrays. `close()` clears the mount.

`openViewerTab` defaults to `true`. After a successful build, the app validates
the generated bytes through DerEditor Core and opens them in a new editable
DerEditor tab. Popup or browser-storage failures do not change the successful
build result; the build status and API Log report the display failure. Hosts
that consume `result.document.der` directly can set `openViewerTab: false`.

Definition Bundle helpers include throwing and diagnostic-returning JSON
parsers, validation, entry lookup, sample/profile extraction, and schema-source
type guards. Unknown JSON fields are accepted and retained in parsed objects.

## Styles

Import `@pkistudio/derbuilder/styles.css` once when embedding the app. The Core
and Validation entry points do not depend on the DOM or CSS.

## Compatibility

The initial package does not provide aliases for legacy package names or the
legacy DOM prefix. Public API evolution follows semantic versioning.

## Initial API decisions

- `build()` uses a discriminated result union so a host always receives either
  generated bytes or a structured failure with diagnostics.
- Definition Bundle and UI Profile APIs remain under the App entry point; they
  do not receive independent package exports in `0.1.0`.
- Direct DER download and HEX clipboard actions are not separate DER Builder
  features in `0.1.0`; generated output uses DerEditor's public save workflow.
- Direct generation failures use the public `DerBuilderError` class.
- The package root re-exports primary validation functions during the `0.x`
  series. This convenience surface will be reviewed before `1.0.0` rather than
  removed in a patch release.
- The normal app uses Definition and Instance/Diagnostics panes with an API
  Log. A successful build opens an editable DerEditor viewer in a new tab.
- DER Builder owns a versioned, one-shot same-origin transfer for whole
  generated documents. DerEditor's internal transfer keys remain outside the
  integration contract; its public `subtree` and `expand` transfer modes are
  still accepted.
